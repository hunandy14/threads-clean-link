# Threads Clean Link

一鍵把 Threads 的分享連結和「複製連結」結果,都變成不帶追蹤參數的乾淨貼文網址。

## 兩大功能

### 右鍵還原分享短連結

Threads App 的「複製連結」會產生 `/share/XXXX` 這種短連結。在這種連結上按右鍵,選擇還原選項,就能一鍵把它換成乾淨的貼文網址,並自動複製到剪貼簿。

```
分享短連結  https://www.threads.com/share/AbCdEfGhI
還原結果    https://www.threads.com/@username/post/AbCd123EfGh
```

### 自動淨化網頁版「複製連結」的追蹤參數

Threads 網頁版官方的「複製連結」按鈕,產生的網址本身會夾帶 `?xmt=...` 這類追蹤參數。Threads Clean Link 在背景默默把這段參數濾掉,你貼上的永遠是乾淨網址,不需要額外操作。

## 運作原理

### 分享短連結為什麼不能「直接算」出來?

`/share/XXXX` 是一次性代碼,會關聯到分享者帳號(類似 IG 連結的 `igsh`),對照表只存在 Meta 的伺服器裡,**沒有任何本地端的規則或正則式能把它還原成貼文網址**——這和「網址裡藏了一段編碼過的資訊」不同,短碼本身不含任何可解析的資訊,唯一辦法是實際問伺服器一次:「這個短碼實際指向哪裡?」

具體做法:對短連結發一次**不帶 cookie 的匿名 GET 請求**,讓瀏覽器自動跟隨轉址,取得轉址後的最終網址,再把 `?xmt=...` 之後的追蹤參數切掉,就是乾淨貼文網址。

### 淨化功能為什麼是「零請求」?

這是完全不同的情境。網頁版「複製連結」按鈕按下去的當下,官方程式碼已經準備好完整、正確的目標網址,只是多附加了 `?xmt=...` 之類的追蹤參數——這不需要問任何人,純粹是字串處理。

Threads Clean Link 在 Threads 頁面裡安裝一層「濾網」,攔截頁面**自己**準備寫入剪貼簿的內容,符合 Threads 貼文網址格式就去掉查詢字串再放行。這層濾網只存在於 threads.com 頁面內部,不會主動連線任何伺服器,也只包住網站自己呼叫的剪貼簿寫入,不涉及讀取剪貼簿裡原本的內容。

## 誠實隱私聲明(請務必讀完這段)

這個擴充功能標榜保護隱私,但誠實比行銷話術重要,以下是兩個功能的真實網路行為,一項不省略:

**右鍵還原功能「會」對外發送網路請求。** 使用右鍵選單還原分享短連結時,本擴充功能會在背景向 `threads.com` 發出一次**不帶 cookie 的匿名 GET 請求**,藉此取得短碼實際指向的乾淨網址。效果等同於「用無痕模式點了一次那個分享連結」——原分享者的貼文開啟數會 +1,但這次請求不帶任何登入憑證、不帶 cookie,無法被關聯回你的帳號或身分。這是短碼問題「必須向伺服器問一次」的技術本質決定的,沒有繞過的辦法,我們選擇把它老實寫在這裡,而不是含糊帶過。

**淨化功能「零網路請求」。** 自動淨化「複製連結」追蹤參數的功能,完全在你的瀏覽器本機執行,對已經拿到手的完整網址做字串處理,不會、也不需要對外發出任何請求。這層濾網也**不會讀取剪貼簿裡原本的內容**——它只攔截網站自己主動寫入的動作,你複製的其他文字、其他網站的連結,擴充功能完全看不到也碰不到。

| 功能 | 網路請求 | 讀取剪貼簿 |
|---|---|---|
| 右鍵還原分享短連結 | 有,1 次不帶 cookie 的匿名 GET | 否(只負責寫入還原結果) |
| 自動淨化複製連結 | 零 | 否(只攔截網站自己的寫入,不讀取既有內容) |

**與 ClearURLs 這類純參數清理器的本質差異。** ClearURLs、Linkumori、CleanURL 這類工具標榜零網路請求,做法是拿到完整網址後,用規則庫剪掉已知的追蹤參數(例如 `utm_source`)——整個過程網址本身完整可見,純粹是文字處理,自然不需要連網。但 Threads 的 `/share/XXXX` 短碼**不是參數,是整條網址**,它不含真實目標的任何資訊,規則庫無法從中「剪」出貼文網址,必須先向伺服器兌換一次才有東西可以清理。這正是 Threads Clean Link 拆成兩個功能的原因:短碼還原無法零請求,但一旦拿到完整網址,淨化追蹤參數就能維持零請求。

## 安裝

尚未上架 Chrome Web Store,目前請以「載入未封裝項目」方式安裝:

1. 下載或 clone 這個 repo 到本機
   ```
   git clone https://github.com/hunandy14/threads-clean-link.git
   ```
2. Chrome 網址列輸入 `chrome://extensions`
3. 右上角打開「開發人員模式」
4. 點選「載入未封裝項目」,選擇剛才 clone 下來的資料夾
5. 完成。之後在 threads.com 的分頁上就能使用右鍵還原與自動淨化功能

Chrome Web Store 上架(含註冊費、審查與隱私權說明)是後續規劃,屆時會在此更新連結。

## FAQ / 已知限制

**手機 App 分享出去的連結,會被這個擴充功能淨化嗎?**

不會。這是瀏覽器擴充功能,只在 Chrome 分頁載入 threads.com 網頁版時運作,不是系統層級的剪貼簿監控工具。手機 App 的分享或複製連結,只要沒有經過你電腦上的 Chrome 分頁,擴充功能碰不到、也管不到。

**Meta 改版會不會讓這個擴充功能失效?**

有可能,但風險集中且可控,已知會受影響的變動點都屬於「壞得明顯、修得容易」:

| 風險點 | 說明 | 修復成本 |
|---|---|---|
| 網域更換 | 已有前例:2024 年 threads.net → threads.com | 改一行網域比對規則 |
| share 路徑格式 | `/share/XXXX` 格式變動 | 改一行路徑比對規則 |
| 轉址行為 | 匿名請求不再回傳 302、改跳驗證頁 | 調整請求方式 |
| 貼文網址格式 | `@帳號/post/ID` 格式變動 | 小幅調整解析邏輯 |

功能失效時通常會直接沒反應,而不是悄悄壞掉;修復也通常只需要改一兩行比對規則,不涉及架構重寫。

**為什麼不做成像 ClearURLs 那樣的通用型追蹤參數清理器?**

刻意把範圍維持小:這個擴充功能只做 Threads、只做這件事。通用型清理器已經有成熟方案,但它們都不處理「短碼問題」——這正是本專案存在的理由。
